================================================================================
PROJECT: MOEIN - Complete Educational Platform (React + Vite)
================================================================================

OVERVIEW
--------
Moein is a full-stack learning and course management application built with React,
Vite, and Formik. It features authentication (Login/SignUp), a comprehensive courses
management system, lecture management with nested modals, light/dark theme toggle,
and localStorage caching for offline-fast UX. The frontend communicates with a
Django-based backend API at http://localhost:8000/api.

================================================================================
TECH STACK
================================================================================
Frontend:
  - React 19.2.0 - UI library
  - Vite 7.2.4 - Build tool & dev server
  - Formik 2.4.9 - Form state management
  - Yup 1.7.1 - Schema validation
  - Axios 1.13.2 - HTTP client
  - ESLint 9.39.1 - Code linting

Styling:
  - Pure CSS3 with CSS variables

  - Light/Dark theme support

5. SRC/APP.JSX

import { useState, useEffect } from "react";
import Login from "./pages/Login";
import SignUp from "./pages/SignUp";
import Courses from "./pages/Courses";

function App() {
  const [page, setPage] = useState("login");
  const [theme, setTheme] = useState("light");

  // Update document theme attribute when theme state changes
  useEffect(() => {
    try {
      document.documentElement.setAttribute("data-theme", theme);
    } catch (e) {
      // Fallback for non-browser environments
    }
  }, [theme]);

  const toggleTheme = () => setTheme((t) => (t === "light" ? "dark" : "light"));

  return (
    <div className="app-container">
      {/* Theme toggle - top right */}
      <div style={{ position: "absolute", top: 12, right: 12 }}>
        <button
          type="button"
          className="btn"
          onClick={toggleTheme}
          aria-label="Toggle theme"
        >
          {theme === "light" ? "Switch to Dark" : "Switch to Light"}
        </button>
      </div>

      {/* Page navigation - top left */}
      <div style={{ position: 'absolute', top: 12, left: 12, display: 'flex', gap: 8 }}>
        <button className="btn" onClick={() => setPage('login')}>Login</button>
        <button className="btn" onClick={() => setPage('signup')}>Sign Up</button>
        <button className="btn" onClick={() => setPage('courses')}>Courses</button>
      </div>

      {/* Page content rendered based on state */}
      {page === "login" && <Login goToSignUp={() => setPage("signup")} />}
      {page === "signup" && <SignUp goToLogin={() => setPage("login")} />}
      {page === "courses" && <Courses />}
    </div>
  );
}

export default App;

KEY FEATURES:
- Manages global page state (login/signup/courses)
- Manages theme state and syncs to document.documentElement
- Provides top-left navigation buttons to switch pages
- Centers all content via .app-container Flexbox
- Theme toggle button in top-right corner

import * as Yup from 'yup';

export const LoginSchema = Yup.object().shape({
  username: Yup.string()
    .required('Username is required')
    .min(4, 'Username must be at most 4 characters'),
  password: Yup.string()
    .required('Password is required')
    .min(6, 'Password must be at most 6 characters'),
});

export const SignUpSchema = Yup.object().shape({
  username: Yup.string().required('Username is required'),
  email: Yup.string()
    .email('Invalid email')
    .required('Email is required'),
  phone: Yup.string()
    .matches(/^[0-9]+$/, 'Phone must be digits only')
    .required('Phone is required'),
  password: Yup.string()
    .min(6, 'Password must be at least 6 characters')
    .required('Password is required'),
  confirmPassword: Yup.string()
    .oneOf([Yup.ref('password'), null], 'Passwords must match')
    .required('Confirm Password is required'),
});

Provides Yup validation schemas for Formik forms. Validates on form submission
and can validate on mount. Error messages are tied to schema.

import { Formik, Form } from 'formik';
import { loginUser } from '../api';
import { LoginSchema } from '../constants/validation';
import { loginValues } from '../constants/values';
import InputField from '../components/forms/InputField';

const Login = ({ goToSignUp }) => {
    const onSubmit = async (values, formik) => {
        try {
            const res = await loginUser(values);
            console.log('Login success:', res.data);
        } catch (err) {
            console.error('Login failed:', err);
        }
        formik.setSubmitting(false);
    }

    return (
        <div id='login'>
            <h2>Login</h2>
            <Formik
                initialValues={loginValues}
                validationSchema={LoginSchema}
                onSubmit={onSubmit}
                validateOnMount={true}
            >
                {({ isSubmitting, isValid }) => (
                    <Form>
                        <InputField name="username" placeholder="Enter username" label="username" type='text'/>
                        <InputField name="password" placeholder="********" label="password" type='password'/>
                        <div className="form-actions">
                            <button type="submit" className="btn btn-primary btn-full" disabled={isSubmitting || !isValid}>
                                Login
                            </button>
                            <div style={{ marginTop: 8, textAlign: 'center' }}>
                                <button type="button" className="btn btn-primary btn-full" onClick={() => goToSignUp && goToSignUp()}>
                                    Sign Up
                                </button>
                            </div>
                        </div>
                    </Form>
                )}
            </Formik>
        </div>
    );
};

export default Login;

KEY POINTS:

- validateOnMount ensures submit button is disabled until valid
- Two buttons: Login (submit) and Sign Up (navigates to signup page)

HOW IT ALL FITS TOGETHER
================================================================================

USER FLOW:

1. APP LOADS
   - App.jsx renders with page="login" and theme="light"
   - Global CSS variables applied
   - Login.jsx displayed

2. LOGIN/SIGNUP FLOW
   - User enters credentials in Login.jsx
   - Formik validates using LoginSchema
   - On submit: loginUser() called via api.js
   - Error/success logged to console
   - User can click "Sign Up" to go to SignUp.jsx
   - SignUp.jsx validates with SignUpSchema
   - On submit: signupUser() called
   - User can return to login or navigate to Courses

3. NAVIGATE TO COURSES
   - Click "Courses" button in top-left nav
   - App.jsx sets page="courses"
   - Courses.jsx mounts
   - useEffect loads cached courses
   - useEffect simultaneously fetches fresh courses
   - Courses grid displayed with cards
   - FloatingButton visible in bottom-right

4. CREATE COURSE
   - Click '+' FloatingButton
   - Course creation modal opens
   - User fills CourseForm (name, instructor)
   - On submit:
     a. Optimistic course added to grid immediately
     b. POST /courses/ sent to backend
     c. Modal closes
     d. "Creating course..." toast shown
     e. Server response replaces optimistic item
     f. "Course created" toast shown (2.5s)
     g. Cache updated
   - On error:
     a. Optimistic item removed
     b. Error toast shown (2.5s)
     c. Cache reverted

5. VIEW COURSE DETAILS
   - Click on a course card
   - Course details modal opens
   - Lectures list loads (cached + fresh)
   - Modal shows:
     * Course name and instructor
     * List of lectures
     * '+ Lecture' button

6. ADD LECTURE
   - Click '+ Lecture' button in course modal
   - Nested lecture creation modal opens
   - User fills LectureForm (title, description)
   - On submit:
     a. Optimistic lecture added to list immediately
     b. POST /courses/{id}/lectures/ sent to backend
     c. Modal closes
     d. "Adding lecture..." toast shown
     e. Server response replaces optimistic lecture
     f. "Lecture added" toast shown (2s)
     g. Course-specific cache updated
   - On error:
     a. Optimistic lecture removed
     b. Error toast shown
     c. Course-specific cache reverted

7. THEME TOGGLE
   - Click "Switch to Dark" button (top-right)
   - App.jsx toggleTheme() updates state
   - useEffect sets document.documentElement.setAttribute("data-theme", "dark")
   - CSS automatically applies [data-theme="dark"] overrides
   - ALL COLORS FLIP (backgrounds, text, inputs, toasts)
   - Button text changes to "Switch to Light"
   - Same process for switching back

8. CLOSE MODAL
   - Click outside modal content (on overlay)
   - Modal closes
   - Modal click handler uses stopPropagation() to prevent accidental close

KEY DESIGN DECISIONS
================================================================================

1. OPTIMISTIC UPDATES
   Why: Immediate feedback makes app feel fast and responsive
   How: Temporary items (tmpId) added before server response
   Risk: If POST fails, need to rollback (implemented)

2. LOCALSTORAGE CACHING
   Why: Offline-fast UX and reduce API calls
   How: Cache on every successful operation
   Risk: Stale data if server changes; mitigated by background fetch

3. CSS VARIABLES + THEME SYSTEM
   Why: Single-point-of-change for theming, no component modifications needed
   How: [data-theme="dark"] overrides all variables
   Benefit: Light/dark modes work everywhere automatically

4. NESTED MODALS (Course > Lectures)
   Why: User stays in course context while adding lectures
   How: Multiple conditional renders in Courses.jsx
   Risk: Complex state; mitigated by clear state naming

5. FORMIK + INPUTFIELD PATTERN
   Why: Consistent form handling and validation across app
   How: InputField component wraps Field + ErrorMessage
   Benefit: Reduces boilerplate, easy to extend

6. AXIOS BASEURL
   Why: Centralized API configuration
   How: Defined in api.js, used by all components
   Note: Update baseURL if backend runs on different port

BACKEND API REQUIREMENTS
================================================================================

The frontend expects these endpoints (assuming Django):

POST /api/login/
  Request: { username, password }
  Response: User object or token (logged to console)

POST /api/signup/
  Request: { username, email, phone, password }
  Response: User object or confirmation

GET /api/courses/
  Response: [{ id, name, instructor }, ...]

POST /api/courses/
  Request: { name, instructor }
  Response: { id, name, instructor }
           OR { course: { id, name, instructor } }

GET /api/courses/{id}/lectures/
  Response: [{ id, title, description }, ...]

POST /api/courses/{id}/lectures/
  Request: { title, description }
  Response: { id, title, description }
           OR { lecture: { id, title, description } }

NOTE: Response shapes are normalized in Courses.jsx:
  const newCourse = (res && res.data && (res.data.course ?? res.data)) || res;

This supports both res.data and res.data.course response structures.

     Verify endpoint path matches backend routes

ISSUE: Dark mode text is unreadable

     Ensure --text, --label-color, --placeholder have adequate contrast
     Run WCAG contrast checker on colors

ISSUE: Modals not closing
FIX: Check modal-overlay onClick is not blocked by event.stopPropagation()
     Verify setShowForm/setSelectedCourse state updates properly
     Check browser console for errors

ISSUE: Courses not appearing
FIX: Check fetchCourses() returns array in res.data
     Verify API GET /courses/ works (test in Postman/curl)
     Check browser Network tab for 200 response
     Check console for fetchCourses error logs

ISSUE: Optimistic course doesn't replace with server response
FIX: Ensure POST response includes 'id' field
     Check response normalization logic in handleCreate()
     Try console.log(newCourse) to see what's being saved
     Verify tmpId matching logic (tmpId === "tmp-...")

ISSUE: Theme toggle not working
FIX: Verify document.documentElement exists (not SSR)
     Check [data-theme="dark"] CSS rules are present
     Inspect element to see data-theme attribute is set
     Check CSS variable values in DevTools

ISSUE: Forms not validating
FIX: Ensure Yup schemas are imported (LoginSchema, SignUpSchema)
     Check validationSchema prop is passed to Formik
     Verify validateOnMount={true} for immediate validation
     Check console for validation errors
