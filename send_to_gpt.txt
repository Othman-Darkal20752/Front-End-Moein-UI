Hi — please review this project and help me optimize or extend it. Below is a complete, structured description of the repo, how it works, and what I want to do next.

Project Summary
- Name: moein (local Vite + React app)
- Purpose: Small learning/management UI: authentication pages (Login/SignUp), course management (list/create), and lecture management (add lectures to courses). Courses and lectures are persisted to a backend API and locally cached for offline-fast UX.
- Stack: React (JSX) + Vite, Formik for forms, Yup used for validation patterns, Axios for HTTP, ESLint for linting.

How to run
- Install deps and start dev server:
  - npm install
  - npm run dev (Vite will serve the app, e.g. http://localhost:5173)
- Backend base URL is set in src/api.js as http://localhost:8000/api (assumes a Django-like API).

High-level features
- Login and SignUp pages (Formik forms, validation integration).
- Theme toggle (Light / Dark) and centered form layout.
- Courses page: list of courses fetched from backend, cached in localStorage, floating + to create courses (modal).
- Optimistic UI for creating courses and lectures: temporary items show immediately, replaced after server response, rolled back on error.
- Course details modal: shows lectures and allows adding new lectures (nested modal).
- Simple toasts messages for feedback and accessible keyboard interactions for cards and modals.

Important files & responsibilities
- src/api.js
  - Exposes: loginUser, signupUser, fetchCourses, createCourse, fetchLectures(courseId), createLecture(courseId, data).
  - Base axios instance: baseURL: 'http://localhost:8000/api'.
  - If backend requires auth, add token handling (interceptors / default headers).
- src/App.jsx
  - Manages page selection (login, signup, courses) and theme state.
  - Writes data-theme to document.documentElement to toggle CSS variables.
  - Top-left nav buttons to switch pages and top-right theme toggle.
- src/index.css
  - CSS variables for light theme; [data-theme="dark"] overrides.
  - Utility classes: .btn, .btn-primary, .btn-outline, .fab, .course-card, .modal-overlay, .modal-card, .toast, etc.
  - Accessibility: :focus-visible outlines, keyboard support for actionable elements.
- src/pages/Courses.jsx
  - Loads cached courses from localStorage (courses_cache_v1) and then refreshes from backend.
  - Uses optimistic updates when creating a course:
    - Inserts a temp object (e.g. id: "tmp-...") to the list immediately.
    - After POST completes, replaces the temp with returned server object (supports res.data and res.data.course shapes).
    - On failure, rolls back and shows an error toast.
  - Clicking a course opens a details modal (selectedCourse) which:
    - Shows lectures (fetched via fetchLectures(courseId) and cached per course key lectures_cache_{id}).
    - Has a + Lecture button that opens a nested modal to add a lecture (optimistic).
  - UI notes: clickable cards (role="button", tabIndex=0, onKeyDown Enter to open), modal overlay click-outside to close, and stopPropagation to prevent accidental closes.
- src/components/*Form.jsx
  - Use Formik Formik + Form and InputField components for consistent label + error rendering.
  - Buttons use .btn utilities and show "Creating…" / "Adding…" while submitting.

UX details & behavior
- Caching: localStorage caches reads for faster UI and to survive refresh. Keys:
  - courses_cache_v1
  - lectures_cache_{courseId}
- Optimistic creation:
  - Temporary IDs (prefixed tmp-) are used locally until server returns real id.
  - Code replaces temporary objects with server response, normalizes possible response shapes:
    - Server returns course as res.data or res.data.course; lecture as res.data or res.data.lecture.
  - On server error, optimistic items are removed (rolled back), and a toast shows an error.
- Theme:
  - data-theme attr toggles CSS variables for dark mode.
  - Toggle is in the top-right of App.jsx. Not persisted to localStorage yet (optional).
- Accessibility:
  - Buttons and cards are keyboard accessible, :focus-visible outlines provided.
  - Modals can be closed by clicking outside; internal clicks stop propagation.

Known assumptions & caveats
- Backend endpoints:
  - GET /api/courses/ returns an array of course objects.
  - POST /api/courses/ returns the created course (object) — code normalizes a few shapes.
  - GET /api/courses/{id}/lectures/ returns lecture list for a course.
  - POST /api/courses/{id}/lectures/ creates and returns a lecture object.
- Authentication & CORS:
  - If backend requires auth tokens or has different CORS headers, the api axios instance must be updated (interceptors / Authorization header).
- Response shapes:
  - The frontend currently supports res.data as the object or res.data.course / res.data.lecture. If your API returns a different structure (e.g., { success: true, data: {...} }), I need a sample response to adapt code.
- Validation:
  - Forms use Formik; Yup schemas exist for login/signup patterns. Course & lecture forms do not yet enforce validation (I can add Yup schemas quickly).
